---
title: Install and set up
description: Install flume from its releases, set up the host's configuration and the agents' settings in layers, and add the herdr and Claude Code plugins.
---

flume is one binary, `flume`, for Linux and macOS. It needs `git` on the
`PATH`, Claude Code for the agents it starts, and, to open them in panes
of their own, herdr 0.9.5 or later. Without herdr, flume prints each
stage's command for you to run.

## Install from the releases

Each release on
[GitHub](https://github.com/agentplot/flume/releases) is tagged
`v<version>` and carries one archive per platform, each holding the
`flume` binary:

| Platform | Archive |
|---|---|
| Linux, x86-64 | `flume-x86_64-linux.tar.gz` |
| Linux, ARM64 | `flume-aarch64-linux.tar.gz` |
| macOS, Apple silicon | `flume-aarch64-darwin.tar.gz` |

The Linux builds are static, so they run on any distribution. Unpack
the archive into a folder on your `PATH`:

```sh
version=v0.1.0
curl -fsSL "https://github.com/agentplot/flume/releases/download/$version/flume-aarch64-darwin.tar.gz" |
  tar -xz -C ~/.local/bin flume
flume --version
```

A release comes out of every landing on `main` whose commits call for a
new version, and its notes list those commits.

## The host's configuration

flume reads one file on the host, `$XDG_CONFIG_HOME/flume/config.toml`,
`~/.config/flume/config.toml` by default, at each agent's start. Every
part of it is optional:

```toml
[host]
# The bound on agents running at once, every caller's counted together;
# with none, every stage starts at once.
agents = 4
# Where agents run: "herdr", or "printed" for a command flume prints.
terminal = "herdr"
```

flume keeps its state under `$XDG_STATE_HOME/flume`,
`~/.local/state/flume` by default: one document per place, gone when the
place is tidied. Nothing of flume's is written into a repository.

## Agents' settings and roles

The same file gives each kind's agents their model and instructions. It
declares the streams the host runs its places in and the pools of
accounts its agents run under, and names the runs the host launches for
role addresses.
[Agent settings](/flume/guides/agent-settings/) and
[roles and wake](/flume/guides/roles-and-wake/) say how, and the
[configuration reference](/flume/reference/configuration/) lists every
key.

## The herdr plugin

Install it at the tag of the flume you run, so the plugin and the binary
are one version:

```sh
herdr plugin install agentplot/flume/plugins/herdr --ref v<version>
```

It needs `flume` and `jq` on the `PATH` herdr's server runs with, and
`terminal = "herdr"` under `[host]`. It brings:

- **the watch**, one per herdr server, which runs `flume settle` when
  one of flume's agents changes state, when an agent comes up or goes
  in one of the server's panes, and every thirty seconds. A place
  moves on with no command of yours, and the watch reads an agent that
  crashed, hung or was killed within that bound;
- **a row on each agent's sidebar entry**, such as
  `change · code · working · 2/5`, and a count on each workspace's row
  of its places running, asking, waiting on their caller and stalled;
- **a popup** of every place in flight, where a key opens a place's
  tab, tells its agent, stops it or retries its stage, each through
  flume's own commands.

The plugin changes none of herdr's configuration: add its key and the
sidebar rows to herdr's `config.toml` yourself, as
[places and herdr](/flume/guides/places-and-herdr/#the-herdr-plugin)
shows.

## The Claude Code plugin

flume writes its plugin itself, for each agent it starts, and hands it
to the agent with `--plugin-dir`, so an agent's hooks always match the
binary that started it. Nothing needs installing for that.

For `/launch` and status in your own sessions, add flume's marketplace
and install the plugin from it:

```text
/plugin marketplace add agentplot/flume
/plugin install flume@flume
```

`/launch <brief>` then chooses a kind and a name with you and runs
`flume launch`. The plugin also serves `flume status` over MCP. Its
hooks do nothing in a session flume did not start.

## The repository

flume's own kinds all land, so a repository binds the merge queue they
land through, and for a change the change tool, in its
`.config/flume.toml`:

```toml
[profiles]
place = "git-worktree"
change = "openspec"
merge_queue = "sluice"
```

A launch of a kind that lands, in a repository that binds no merge
queue, is refused. The binding is read at the repository's default
branch. [Launching a fix](/flume/guides/walkthrough/) goes on from
here.

A pane's shell reads no startup files, so flume hands the agent your
login environment. Text beyond ASCII in a prompt reaches the agent whole
only when that environment sets a UTF-8 locale, such as
`LANG=en_US.UTF-8`.
